# 0.3.0 — ACE Kernel Exports and Installation Docs

Builds on 0.2.0 (NIKKE 152.8.11 compatibility) by adding the **kernel exports
required by ACE**, plus complete installation and update documentation.

Verified on: Apple M4 Max, macOS 27.0, CrossOver 26.1, NIKKE 152.8.11 (Global).

---

## 1. Why this patch is needed

0.2.0 already reached the lobby and completed battles. In real use, however:

```
err:module:import_dll Library ntoskrnl.exe
     unimplemented function ntoskrnl.exe.KeAcquireGuardedMutex
```

ACE (Anti-Cheat Expert) calls a set of `ntoskrnl.exe` routines that CrossOver
does not implement. When those calls fail, the game refuses to start.

This patch implements them.

## 2. Added kernel exports

`patches/crossover-26.1-ace-kernel-exports.patch` — 3 files, +119 −1

| Export | Implementation |
|---|---|
| `KeTryToAcquireGuardedMutex` | non-blocking attempt via the underlying fast-mutex counter |
| `KeIpiGenericCall` | runs the callback on the current processor (Wine has no IPI support) |
| `KeGetProcessorNumberFromIndex` | returns processor 0 on a single-CPU system |
| `KeSetSystemGroupAffinityThread` | records the affinity setting |
| `KeRevertToUserGroupAffinityThread` | restores affinity |
| `ObDereferenceObjectDeferDelete` | deferred-delete dereference |
| `PsGetCurrentThreadTeb` | returns the current thread TEB |

### Design principle

**Failed interface queries are never replaced with a hardcoded success.**

- `MmCopyMemory` is newly exported but still **explicitly returns unsupported**
- unsupported kernel thread contexts likewise **return failure**

This keeps "works" distinguishable from "pretends to work", which matters when
diagnosing later problems.

### Better diagnostics

`KeBugCheck` / `KeBugCheckEx` now log the call site and a stack walk:

```c
ERR( "KeBugCheck %lx called from %p\n", code, __builtin_return_address(0) );
for (i = 0; i < 24; i++) ERR( "  stack[%d] = %p\n", i, (void *)sp[i] );
```

When a major game update introduces new calls, the missing piece can be
identified straight from the log instead of by trial and error.

## 3. An important correction

**Our built `ntoskrnl.exe` is a superset of CrossOver's.**

During installation, CrossOver's stock `ntoskrnl.exe` was mistakenly restored,
and ACE immediately refused to start with `unimplemented function`.
Reverting to our build fixed it.

Therefore:

> ⚠️ **Never** overwrite this project's `ntoskrnl.exe` with CrossOver's.

This is now documented under troubleshooting.

## 5. Build integration

The new patch is wired into the patch sequence in
`scripts/build_wine_modules.py`:

```python
PATCHES = ("crossover-26.1-kernel.patch",
           "crossover-26.1-thread-process-experimental.patch",
           "crossover-26.1-september-update.patch",
           "crossover-26.1-ace-kernel-exports.patch",   # <- this release
           "crossover-26.1-mf-software.patch")
```

`scripts/prepare_runtime.py` already lists `ntoskrnl.exe` among the runtime
replacements, so the built module is copied into the prefix's `system32/`.
