# 0.3.0 — ACE 内核导出补全与安装文档

在 0.2.0（NIKKE 152.8.11 适配）基础上，补齐 **ACE 反作弊所需的内核导出**，
并补上完整的安装/更新文档。

本机验证环境：Apple M4 Max、macOS 27.0、CrossOver 26.1、NIKKE 152.8.11 国际服。

---

## 一、为什么需要这个补丁

0.2.0 已能让游戏进入大厅并完成战斗。但在实际使用中发现：

```
err:module:import_dll Library ntoskrnl.exe
     unimplemented function ntoskrnl.exe.KeAcquireGuardedMutex
```

ACE（Anti-Cheat Expert）反作弊组件在启动时会调用一批
**CrossOver 未实现的 `ntoskrnl.exe` 内核接口**，
调用失败直接导致游戏拒绝启动。

本次补丁把这批接口补上。

## 二、新增的内核导出

`patches/crossover-26.1-ace-kernel-exports.patch`
（3 文件，+119 −1）

| 导出 | 实现方式 |
|---|---|
| `KeTryToAcquireGuardedMutex` | 基于底层 fast mutex 计数器做非阻塞尝试 |
| `KeIpiGenericCall` | 单处理器上直接执行回调（Wine 无 IPI 支持）|
| `KeGetProcessorNumberFromIndex` | 单处理器返回 0 号处理器 |
| `KeSetSystemGroupAffinityThread` | 记录亲和性设置 |
| `KeRevertToUserGroupAffinityThread` | 恢复亲和性 |
| `ObDereferenceObjectDeferDelete` | 延迟删除式解引用 |
| `PsGetCurrentThreadTeb` | 返回当前线程 TEB |

### 设计原则

**不把失败的接口查询替换为固定成功值。**

- `MmCopyMemory` 新增导出，但仍**明确返回不支持**
- 未支持的内核线程上下文同样**返回失败**

这样可以保证「能用」与「假装能用」可区分，便于后续定位问题。

### 增强的调试输出

`KeBugCheck` / `KeBugCheckEx` 增加了调用点与栈回溯输出：

```c
ERR( "KeBugCheck %lx called from %p\n", code, __builtin_return_address(0) );
for (i = 0; i < 24; i++) ERR( "  stack[%d] = %p\n", i, (void *)sp[i] );
```

这样游戏大版本更新引入新接口时，能直接从日志定位缺失项，
而不必盲目试错。

## 三、一个重要的认知修正

**本项目构建的 `ntoskrnl.exe` 是 CrossOver 原版的超集。**

安装过程中曾误将 CrossOver 原版 `ntoskrnl.exe` 还原回去，
结果立刻导致 ACE 报 `unimplemented function` 拒绝启动。
改回本项目构建的版本后恢复正常。

因此：

> ⚠️ **不要**用 CrossOver 原版覆盖本项目的 `ntoskrnl.exe`。

文档中已把这一点写进故障排查。

## 五、构建流程

新增补丁已接入 `scripts/build_wine_modules.py` 的补丁序列：

```python
PATCHES = ("crossover-26.1-kernel.patch",
           "crossover-26.1-thread-process-experimental.patch",
           "crossover-26.1-september-update.patch",
           "crossover-26.1-ace-kernel-exports.patch",   # ← 本次
           "crossover-26.1-mf-software.patch")
```

`scripts/prepare_runtime.py` 已将 `ntoskrnl.exe` 纳入运行时替换清单，
构建出的模块会被正确复制到前缀的 `system32/`。
